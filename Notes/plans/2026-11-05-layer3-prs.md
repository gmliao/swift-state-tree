# Layer 3: sync phase inside the keeper turn (PR split)

Status: plan, revision 3 (final, 2026-11-05), after adversarial check. Conditional on the spike's go (Q4/Q5 cost runs pending). Builds on #86 (ordered writer + back-pressure) and #91 (plan + commit). Shape: `2026-11-04-room-transaction-architecture.md` rev 3. The spike (#93, `spike/layer3-in-turn-sync`, 672b559) is the reference implementation; nothing is merged from it.

## What the spike established (macOS; Linux pending on #93 CI)

- The identity-checked `LandKeeperTransport` synchronous entry, with the adapter on the keeper's executor, compiles clean in Swift 6 mode. The full `swift test` passes with in-turn sync on and off.
- The tick turn (apply → handler → events → plan/commit → enqueue → clear dirty) is non-async. This synchronous structure is the main evidence; the reentrancy probe and its negative control are supporting evidence (they show the task started, not that it was queued on the executor).
- E2E in all encodings plus the load variant converge with 0 mismatches; replay recordings are byte-identical to the legacy path.
- Two #77 tests depend on a hop window that no longer exists once the executor is shared.

## PR A — the runner

Same protocol, same convergence, **same sync cadence**:

1. **Executor sharing behind a real kill switch.** `unownedExecutor` returns the keeper's executor only when in-turn sync is on, decided once at adapter init. With it off, the adapter keeps its own executor, which gives a true rollback to the legacy behaviour. The adapter's decision is the single source of truth: the keeper's `usesInTurnSync` and `runsSyncPhaseInTurn(of:)` follow it, so a keeper ON with an adapter OFF never reaches `assumeIsolated`. The switch is plumbed through `NIOLandServerConfiguration → NIOLandServer → LandManager → keeper/adapter`, plus the `IN_TURN_SYNC` env var; an explicit OFF anywhere wins. CI runs the full `swift test` with both settings, and one E2E with OFF.
2. **Tick lands keep the legacy cadence.** The sync loop runs a **sync-only turn** at its own interval, a synchronous turn on the keeper's executor, instead of marking the sync due for the next tick. A tick turn includes the sync phase only when a handler requested one (`requestSyncNow` / broadcast-only). Sync timing is therefore unchanged and the turn is atomic. This replaces the spike's "due until next tick" rule, which delayed state frames by up to one tick (the cookie E2E failure on #93 is a candidate symptom). **Coincident-sync rule:** when the sync loop fires and the land's next tick deadline is within `window = min(5 ms, tick/4, sync/4)`, the sync folds into that tick turn instead of running a sync-only turn first, so a sync never overtakes a coincident tick (counter `foldedSyncs`). Spike evidence: without it, cookie E2E failed 4/9 encoding runs; with it, 9/9, base 9/9. cap300 and json50 pass with it (n=1, n=3 pending).
3. **The complete tickless scheduler.** Every tickless entry point runs as a turn: action, client event, join, leave, initialize. Specified rules:
   - one scheduled drain at a time;
   - each turn takes an ordered snapshot of the ready inputs, and inputs arriving during the turn go to the next one;
   - a bounded batch per turn, so continuous input can't starve the sync;
   - the turn applies the inputs, collects events, and calls `runSyncPhaseInTurn(events:)` with the sync phase when any sync was requested (pending requests merge; broadcast-only folds into the turn);
   - responses stay per input, and the freeze in-flight accounting is kept;
   - the recorder runs after the turn.
4. **No lost requests.** A sync-only turn that finds a legacy cycle in flight (`isSyncing`: debug settle, joiner path) keeps the request due and re-runs after `endSync`. A deferral on back-pressure keeps dirty flags and events; periodic lands re-sync on the next sync-only turn, tickless lands retry once after the writer drains.
5. **Failure repair in turns.** On tickless lands, a failed in-turn plan schedules a bounded sync-only repair turn instead of calling `syncNow()`. Periodic lands rely on their next sync-only turn. The bookkeeping (`consecutiveFailedPlans`, follow-up limit) is as in `withSyncState`.
6. **Atomic recorder submission**, as its own commit. One `TickRecord` per turn, containing the inputs, hash, snapshot, server events and W1/W2, submitted in turn order. Several tickless drains in the same tick append and merge into that tick's record and never overwrite its events. Reevaluation stays on its legacy branch.
7. **Events.** json/opcodeJsonArray events are synchronous writer enqueues in emit order, before the turn's state frame. 107: the emit-order guarantee holds per frame kind. The inherited order is merged broadcast → targeted → per-player, so a targeted event emitted before a broadcast one arrives after it. Document this and pin it with a mixed-target 107 test.
8. **Stated limits.** The joiner's firstSync (`await keeper.currentState()`) and OnJoin delivery to the joiner stay outside A's atomicity (#69). The freeze settle still uses `beginSync`/`endSync` and the hold.
9. **Document `stepTickOnce`:** one tick turn; it syncs only when due or requested, can defer on back-pressure, and returning doesn't mean the writer drained.

Tests:
- the spike's suite: probe + control, events decoded in order, 107 in one frame, deferred back-pressure, replay parity;
- the tickless scheduler: batching, arrival during a turn, a starvation bound, every entry point, per-input responses;
- a lost-request test (a sync-only turn during a legacy cycle);
- failure repair through a turn;
- the recorder: overlapping `stepTickOnce`, several tickless drains in one tick, ON/OFF parity;
- freeze/resume interleaved with a deferred writer retry;
- cadence: on a land with tick ≠ sync interval, update-interval p99 ON vs OFF;
- the #77 hop tests run under OFF. Their ON replacement asserts outcomes (events not lost, sent once, the follow-up happens), not just signatures.

Verification:
- core rules: the full `swift test` with ON and OFF, release build, both E2E scripts with gating, the load variant, replay E2E;
- Linux CI;
- the perf A/B against #91's head on the local machine: **300 rooms is the baseline** (5-player rooms; RTT, update, CPU, deferred turns), plus the 50-player json room. Higher room counts on the local machine are informational only; capacity and cross-version comparison numbers come from a separate run on the reference machine.

## PR B — cleanup and API

Gated on these dependencies being gone: the freeze settle (a synchronous capture/settle replaces the hold), the joiner firstSync (#69), and failure repair (done in A).
- Remove the legacy sync path and the kill switch after one release, along with `debugCycleHoldBeforeEndSync`, the hop-era bookkeeping (#82 follow-up after endSync, busy re-run, `beginSyncRequests`) and the hop-window tests.
- Rollback: before PR B, tag and release a version that still has both paths; PR B's removal lands as one squash commit that can be reverted while the surrounding code is still unchanged. Precondition: the reference-machine performance runs are done on the in-turn path, and E2E and load runs stay green.
- Deprecate or remove:
  - `beginSync` / `endSync` / `isSyncing`;
  - external `syncNow` / `syncBroadcastOnly`, which now schedule a sync-only turn;
  - `LandKeeperTransport.syncNowFromTransport` / `syncBroadcastOnlyFromTransport`;
  - `waitForWriterDrainForInTurnSync`;
  - `InTurnSyncResult.unsupported` / `.notRequested`, once every transport supports the entry.
- `sendEventToTransport` stays as long as reevaluation's `.transportAndSink` uses it; decide its home.

## Gates

- The spike's cost runs measured its combined-turn design ("due until next tick"), which PR A doesn't use, so they serve as indicators only. **The deciding measurement is PR A's own A/B**, or a quick sync-only-turn variant of the spike if a decision is needed before PR A exists.
- Spike go (Q4/Q5), restated for the sync-only-turn design:
  - normal room: tick-turn p99 ≤ main's tick p99 + 2 ms, and sync-only-turn p99 ≤ main's sync p99 + 2 ms. A tick turn that folded a sync contains that sync, so when `foldedSyncs` > 0 the tick-turn bound is main's tick p99 + sync p99 + 2 ms;
  - 50-player json room: tick-turn and sync-only-turn p99 each ≤ 50 ms, or ≤ main's with a named mitigation (the folded-turn rule above applies to the relative bound);
  - stated inherent cost: with a shared executor, one land's tick and sync can no longer overlap. The capacity step measures it;
  - capacity no more than one step (100 rooms) below main (local sweep is informational; the reference-machine run is authoritative);
  - Linux CI green on #93, apart from failures that predate the spike and are tracked separately.
- PR A: the A/B at its head, with no regression beyond the spike's numbers; cadence unchanged (update-interval p99 ON vs OFF within noise).
